# 经验启发式v1

控制器名为 `ai_humanexp_heuristics_v1`，Web 和 Tkinter 均显示“经验启发式v1”。
实现位于 `src/powergrid/ai/humanexp.py`，使用既有 `GameSession` 意图接口，支持德国、
美国地图的 3–6 人局，也可用于测试地图场景。既有默认 AI 不变。

原始方案：`docs/ai_humanexp_instructions.txt`。本轮提出的 15 项歧义已通过 app 内问题
逐项确认，并据答复修订实现。后续章节同时记录其他必要的实现约定。

## 首轮拍卖

- 评估某厂时，先假定自己买下该厂，将它从竞对范围中排除。
  剩余尚可买厂的对手有 k 人，竞对集合最多 k 座，范围为剩余当前市场和未来市场
  最小 k 座。已买厂、已放弃整轮者不计；只退出当前竞拍者仍计入。
  因此原例中自己买 #4 后，竞对 #5、#8 成立，#9 不成立。
- “同时竞对 #4、#5”的 #10 优先级使用较低的专门档，不归入“单独竞对 #4 或 #5”档。
  表中未列出的电厂/条件排最后，不主动加价；六人局首轮若提前出现大号厂，也采用此兜底。
- 起拍先筛掉底价超过心理上限的厂，再按偏好排序。仅剩自己可买厂时也遵守心理上限，
  若没有符合上限的可购厂，则选择最低合法起拍价的电厂（包含 1 元特价）作为强制
  购买的兜底，同价时按编号最低者选择。有对手时也采用相同的筛选和兜底规则。
- 每个席位、每座厂、每类拍卖的价位区间采用游戏 seed 确定的固定随机整数；相同区间
  在一局中不会因反复询问而重新抽样。条件改变时按新范围计算，仍使用同一独立随机源。
- 判断是否超过上限使用本次最低合法新报价；“上限−2 至上限−1”使用场上当前报价。
  因此当前报价为上限−1 时，仍需检查是否值得等下一座厂。
- 插头概率是所有未见插头牌的等概率分布，包括可能在开局暗中被移除的牌。
  不使用实际隐藏牌面、顺序或移除清单；只读取顶部牌背。
  新进入当前市场的厂为新抽牌与原未来市场最小厂中编号较小者。
- 比较下一座厂时，假定自己 pass、当前拍卖由另一位玩家获胜，并据更新后的公开
  市场及剩余买家人数重新计算竞对。只统计严格更优的偏好，概率达到 50% 即放弃。

## 后续拍卖与估价

- C、C_i 均为建设后的城市总数，包含已有城市；P 为购买前所有电厂的总发电量。
- 累计认定不足三座终局厂时，最差电厂直接按编号最低判断，不比较发电量。
  已认定三座之后，替换发电量最低的厂，同发电量时编号最低。
  替换先取得新厂再弃旧厂，已存资源可转移到新厂；真正弃厂与估算都采用同一座旧厂。
- 终局厂按实际认定的先后顺序记录，P1、P2 为历史值，不因后来买到更大发电量的厂
  或原厂被弃置而重排、清除。正常从开局运行时，控制器观察实际购厂结果并记录前三座；
  拍卖中的假想候选不会改变历史记录。初次接入缺少历史的中盘场景时，仅能按当前
  持有电厂的顺序初始化，无法从静态快照还原已丢弃厂及真实认定顺序。
- 已持有的旧厂一旦因门槛更新而达标，也立即认定；同一时刻多座达标时按购入先后
  稳定选择。实际拍卖获厂后即重新判断，不推迟到强制弃厂之后；认定记录不会因弃厂清除。
- 累计认定三座终局厂后，新的终局候选须严格超过当前发电量最低厂的发电量，
  不再使用原第三座的发电门槛；购买一律要求 C_i ≥ P+1，C_i == P 不再可拍。
  该限制也适用于 1 元特价厂。三座之后仅按以上两项条件筛选，不再使用原 +2 发电量、
  1.5 倍编号、特价编号比例或购买前的 P/C 缺口条件；替换当前发电量最低厂，同发电量
  时按编号最低者选择。使用购买前已认定的终局厂数量选择本次替换规则。
- 顺位靠后者按实际购买顺序估计资源需求，每厂 1.5 倍需求向上取整，并扣除
  对方已有储量。拍卖阶段每座可能成为竞对的可见厂另计 0.5 倍需求、向上取整。
  每次需求都先消耗估算市场，再为自己报价。
- 混合厂枚举煤/油组合，优先使用可供给且便宜的组合，不同时把完整需求加到煤和油。
  有专烧厂时，储存资源先共同满足全部需求，避免同一份煤被重复计入。
- 资源供应不足时视为无法为该组合完整补给；不凭空补入市场资源。
- 城市估算复用地图连接成本与占位费用，逐城选择最便宜合法目标，每座增加
  顺位靠后玩家人数对应的费用。拍卖估算不受发电量建设上限限制。
- 免费发电厂的性价比视为无穷大；同类同分时按较低编号稳定决胜。
- 特价厂底价为合法 1 元，其余厂底价为编号。竞价溢价 m 在支付底价、全部补给以及
  达到所需 C_i 门槛的建设费用后计算；不需要满足全部最大可建城市的预算。
  特价厂若不满足 C_i 门槛，只会以 1 元起拍，不会继续竞价。

## 购买资源、建设与发电

- 枚举电厂子集及混合配比，结合现有储量和市场购买成本，比较
  `发电收入 − 本次资源开销`。同分时优先资源支出更低、可建城市更多、购买数量更少者。
- 资源阶段的建城预测使用当前发电量上限及第一顺位例外，并加入城市争抢修正。
- 资源缺口按全场所有电厂运行一次的需求减去当前 step 的补充量，不扣玩家储量；
  混合厂按当前市场较便宜的组合分配。只有正缺口才囤货，按缺口降序，直至无钱或无空间。
  先预留最优方案的建城资金，再用剩余资金囤货。相同缺口依煤、油、垃圾、铀排序。
- 由于 Session 按煤、油、垃圾、铀依次询问，每次买资源开始时先制定完整采购方案，
  后续按顺序执行，避免先购资源挤占更优先资源的预算；不能补购已跳过的资源。
- 每位有城市网络的对手，按真实总建设费用选其最便宜三个合法目标，修正 −2、−1、−1；
  多位对手争同一城时修正累加。没有网络的对手没有“相邻城市”，不产生修正。
  修正只决定优先级，实际支付金额始终使用规则引擎的真实费用。
- 自己当前为第一顺位，且按本轮可负担建设结果比较城市数、最大电厂编号后仍可第一，
  则允许超发电量建设。完全同分沿用本轮顺序，故原第一仍为第一。
- 发电枚举所有合法组合与混合配比，最大化实际供电城市；相同供电时少消耗资源。
  弃混合燃料时优先弃当前单价较低的燃料，保留较贵燃料。

## 运行与验证

```bash
PYTHONPATH=src python -m powergrid.tools.run_ai_game \
  --controllers ai_humanexp_heuristics_v1 --seed 7
PYTHONPATH=src python -m unittest tests.test_humanexp_ai tests.test_web tests.test_ai tests.test_session -q
```

策略日志标签为 `humanexp_heuristics_decision`，包括出价上限、换牌概率、候选厂经济
估算、历史终局厂、资源组合、建城预留金额和城市争抢修正。实现不会更改传入快照。
